# Публикация в RuStore и Google Play

Зачем: ссылку на магазин родителям отправить проще и спокойнее, чем «скачайте APK» из мессенджера — магазин проверяет файл, подпись и обновляет приложение сам.

## 0. Что уже готово в проекте

- Идентификатор приложения: `com.gesys.piano_notation` (после первой публикации менять нельзя).
- Версия берётся из `pubspec.yaml` (`version: 1.1.0+2` → имя `1.1.0`, versionCode `2`). **Перед каждой новой загрузкой в магазин увеличивай число после `+`.**
- Release-сборка подписывается ключом из `android/key.properties` (см. шаг 1). Без этого файла собирается debug-подписью — магазины такой файл не примут.
- В релизной сборке у приложения **нет ни одного разрешения** (INTERNET есть только в debug для разработки) — это упрощает анкеты магазинов.
- targetSdk 36, minSdk 24 (Android 7.0+).
- Политика конфиденциальности: [PRIVACY.md](../PRIVACY.md), ссылка для магазинов: https://github.com/elektrokips-art/piano_notation/blob/master/PRIVACY.md
- Тексты карточки: [STORE_LISTING.md](STORE_LISTING.md)

## 1. Ключ подписи

Ключ уже создан: `android/upload-keystore.jks`, пароли в `android/key.properties` (оба файла игнорируются git'ом). **Файл ключа и пароли потерять нельзя** — без них нельзя выпускать обновления в RuStore. Сделай копию в надёжное место (облако с паролем, флешка).

Если нужно создать ключ заново (на другом компьютере), команда такая (`keytool` лежит в `jbr\bin` Android Studio; путь к Java показывает `flutter doctor -v`), потом скопируй `android/key.properties.example` в `android/key.properties`:

```powershell
keytool -genkeypair -v -keystore android\upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
```

## 2. Сборка

Одной командой (проверка кода, APK, AAB, проверка подписи, копирование файлов в `Desktop\Piano\build`):

```powershell
powershell -ExecutionPolicy Bypass -File tools\build_release.ps1
```

Или вручную:

```powershell
flutter build appbundle --release   # для Google Play -> build/app/outputs/bundle/release/app-release.aab
flutter build apk --release         # для RuStore    -> build/app/outputs/flutter-apk/app-release.apk
```

## 3. RuStore (https://www.rustore.ru/developer)

- Регистрация в консоли; физлицо проходит верификацию по паспорту. Бесплатное приложение без платежей — статус ИП не нужен (он требуется только для платежных инструментов RuStore).
- Загрузить APK/AAB, добавить описание, скриншоты, иконку, ссылку на политику конфиденциальности, возрастной рейтинг 0+.
- Приложение проходит модерацию перед публикацией.

## 4. Google Play (https://play.google.com/console)

- Аккаунт разработчика — разовый взнос 25 $ + проверка личности.
- Для **личного** аккаунта, созданного после 13.11.2023: перед выходом в продакшен нужен закрытый тест минимум с 12 тестерами, которые подряд 14 дней остаются подписанными на тест. Тестеры — родители/учителя школы (нужны их Gmail-адреса). Просят, чтобы они реально открывали приложение.
- Анкеты: «Безопасность данных» (данные не собираются), рейтинг контента, целевая аудитория, «Политика конфиденциальности» (ссылка выше).
- Загружать `.aab`, не `.apk`. Включить Play App Signing (предлагается по умолчанию): ключ из шага 1 станет «ключом загрузки».

## 5. Перед каждым релизом

1. `flutter analyze`
2. Поднять `+N` в `pubspec.yaml`
3. Собрать AAB/APK, проверить на телефоне
4. Загрузить в консоль, описать «что нового»
